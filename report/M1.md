## Requirements:
- Total user = 100k users at EU-West 
- Avg Requests per User per Day = Loading Feed (~100 req) + Upload image (~2 req) + User Engagement (like posts, comments) (~40 req) = 140
DAU = 30k 
- Total Requests per Day = 140 * 30 = 4200 
- RPS = (DAU × Avg Requests per User per Day) / 86,400 = 49

## Feature of the system:
- Register/Login (bypassed in load testing)
- Upload posts(with caption)
- Like/Comment and view their count 
- Home feed 
- Follow/Unfollow (not tested in load testing)

## Tech-stack:
- PostgresSQL
- Spring boot
- k6 (for load testing)

## Assumptions:
- No celebrities
- No viral post
- Everybody can like/comment everybody posts (so no private account feature)
- All users are in EU-West

---
I choose monolithic architecture with PostgresSQL at this scale since actual expected RPS = 49
can be handled with a properly indexed relational database. As the system grows and different components require
independent scaling or deployment, a microservice architecture could be considered. For the 
current scale, however, the additional complexity introduced by distributed services is not 
justified. For more architecture details, see 
[architecture diagram](../architecture)

## Note:
For load testing, I bypass login mechanism.

pre-populated with approximately 500,000 posts, 2.5 million likes, 100,000 registered users 
and 1 million follow relationships. The CSV files used to seed the database are available in 
[csv files](../data_seed)
